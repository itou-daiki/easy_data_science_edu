# Iteration 21: easyStat準拠の生成AI支援

## 目標

`easy_stat_edu` の生成AI支援を参考に、APIキーがなくてもAI用テキストをコピーでき、APIキーがある場合はGeminiで解釈生成できる設計へ揃える。あわせて、AIへ渡すプロンプトを信頼性・妥当性チェックとレポート例を含む教育向け形式に強化する。

## タスク

- [x] 1. easyStatの生成AI支援UI・状態管理・プロンプトを確認する
- [x] 2. APIキー未設定でもAI補助パネルとコピーを利用可能にする
- [x] 3. Gemini送信とコピーの説明文・ボタン状態をeasyStatの思想に揃える
- [x] 4. AIプロンプトを信頼性・妥当性チェックとレポート例込みに強化する
- [x] 5. easyStatの追加質問・Geminiフォールバックの扱いを確認する
- [x] 6. APIキー有効時に分析結果へ追加質問できるUIとプロンプトを追加する
- [x] 7. Geminiモデル呼び出しのフォールバックとエラー表示を強化する
- [x] 8. マニュアル更新、静的チェック、差分確認を実施する

## 成功基準

- APIキー未設定でも、結果文脈がreadyなら「AI用テキストをコピー」が使える
- APIキー未設定時は「解釈を生成」が無効になり、コピーは有効のまま
- 変数選択・分析結果生成前はコピーも生成も無効
- コピー内容は信頼性・妥当性チェック、注意点、レポート例を要求するプロンプトを含む
- APIキー有効時は、生成済み解釈または分析文脈に対して追加質問できる
- Geminiモデルが利用不可の場合、既定の安定モデルへフォールバックする
- `node --check`、ES module import確認、`git diff --check` が通る

## レビュー

- `easy_stat_edu` の生成AI支援を確認し、APIキーなしでも「AI用テキストをコピー」を使える設計へ揃えた。
- Gemini APIキー未設定時は「解釈を生成」と追加質問だけを無効化し、コピーは結果文脈がreadyなら有効にした。
- APIキー有効時は、分析結果文脈と直近の会話履歴をもとに追加質問できる入力欄をAI補助パネルへ追加した。
- Gemini呼び出しは、指定モデルが利用できない場合に `gemini-2.5-flash` へフォールバックし、モデル名・APIキー・権限のエラーを区別して表示するようにした。
- APIキー保存・削除時の説明文、設定モーダル、利用マニュアルを、送信範囲とプライバシーが誤解されにくい表現へ更新した。
- AIプロンプトに「信頼性と妥当性チェック」「解釈で注意すること」「レポート例」を必須化し、一般論ではなく表示済みの数値とモデル名に基づく解釈を求めるようにした。
- 変数選択・モデル比較前は引き続きコピー、生成、追加質問を無効にし、分析結果生成後にコピーできる条件を維持した。
- `node --check`、ES module import確認、`git diff --check` は成功。

# Iteration 22: Splyzaライクな動画分析タブ

## 目標

スポーツ・行動分析向けに、ブラウザ上で完結する動画分析機能（Splyzaクローン）を新タブとして追加する。
既存のAutoMLワークフローとは独立した「動画分析」カテゴリを作り、ローカル動画の再生、コマ送り、描画アノテーション、タグ/イベント記録、2動画の同期比較、MoveNetによるポーズ推定までを一連で扱う。

## スコープ

- 既存SPAに新タブとして統合（`feature-card[data-analysis="video_analysis"]` を追加、`data-requires="none"`）。
- すべてブラウザ完結、ファイル送信なし。動画は `<video>` + `URL.createObjectURL` で扱う。
- TensorFlow.js は既に読み込まれているので、`@tensorflow-models/pose-detection` をCDN追加してMoveNetを利用。
- 教育用途のため日本語UI、配色は新カテゴリ色（紫系 #7c3aed 想定）。

- 動画分析タブを `js/analyses/video_analysis.js` (entry) + `js/analyses/video_analysis/{annotation,pose}.js` のサブディレクトリ構成で追加。

  - 大規模化を見越し、描画システムとMoveNet周辺は責務単位でファイル分離。
- 単一/比較モードを切替可能にし、Aを基準にBを `currentTime + offset` でクランプ同期。speed/play/pauseもA→Bへ伝播。
- 描画は正規化座標 (0〜1) で保持し、解像度の異なる動画でも一貫表示。表示は currentTime ∈ [time, time+durationSec] で自動表示・フェードアウト。
- タグはタグ定義（共有ボキャブラリ）と打刻イベント（target別）を分離し、ホットキー1〜9で打刻。タイムラインバーに色付きマーカーを描画。
- ポーズ推定は `@tensorflow-models/pose-detection` の MoveNet SinglePose Lightning を使用。WebGLバックエンド優先、関節6点（左右肘/膝/肩）の角度を計算しPlotlyで時系列表示。
- スタイルは既存の `category-{name}` 規約に従って `category-video` を追加、テーマ色 #dc2626。CSS変数 `--va-theme` 経由で枠・ボタン・バッジの色を統一。
- 既知の改善余地: 23の `manual.html` 反映、Playwright MCP実機シナリオ自動化、ResizeObserverを使ったキャンバス追従の最適化。

# Iteration 22+1: UI改善 + 画像対応

## 追加スコープ

- 画像（jpg/png/webp/gif/bmp）も同タブで読み込めるようにする。
- レイアウト・コントロールの視認性を上げ、Splyzaライクの教育用ツールとしての完成度を上げる。

## 主な変更

- `_createTargetState` に `mediaType` / `media` / `image` を追加。`<video>` と `<img>` を同一の `va-video-wrap` 内に並列配置し、`mediaType` で表示を切替。
- 描画は画像時 `showAll` で常時表示。`renderAnnotations` に `options.showAll` を追加。
- ポーズ推定は `<video>` / `<img>` どちらでも単発推定可能。`detectPoseOnce(media)`/`drawPoseOverlay(...media)` に汎用化。連続推定は動画のみ許可。
- タグは動画のみ。画像時に打鍵すると alert で説明。
- 同期バーは両側動画時のみ有効化。混在時はメッセージ「同期再生は両側が動画のときだけ有効です。」へ切替。
- 再生/一時停止を 1 つの円形プライマリボタン (`va-btn-play`) に統合。アイコン自動切替・は再生中はやや暗赤色。
- 時刻表示はモノスペース・ピル背景化、画像時は「静止画」表示。
- アクティブパネルに赤いリング枠（`va-panel-active`）を付与し、対象が一目で分かるように。
- メディアタグ（動画/画像）チップを各パネルヘッダに追加。
- 描画ツールバーをアイコン付きグリッドに刷新。
- 同期バー色を黄→青に変更（情報系として誤誘導を避ける）。
- ドロップゾーンを大きく、円形アイコン + CTA ボタン入りに刷新。
- カスタム seek バー（赤グラデ + 白サム）。
