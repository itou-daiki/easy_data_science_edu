# Lessons

## 2026-05-03

- ユーザーが参考リポジトリと作成対象リポジトリを併記している場合、最初に「参考元」と「編集対象」を明示的に分離してから作業する。URLが1つだけ先に提示されても、文脈上の対象確定を急がない。

## 2026-05-04

- 分析結果UIで係数・重要度・確率を表示するときは、アルゴリズムごとの意味を分ける。線形系は係数、木系は重要度、KNNは近傍設定、SVMは未キャリブレーション確率の注意、Naive Bayesは事前確率・分布仮定を明示し、同じ「重要そうな数値」として一括表示しない。

## 2026-05-09

- 同じDOM要素を再利用するUI（例：動画プレイヤー上の `<video>` を素材切替して使い回す）では、要素のイベントリスナーは初回構築時に一度だけ取り付ける。`_loadVideo` のような再呼び出し関数の中で `addEventListener` を重ねると、同一イベントが多重発火して誤ってBの動画を勝手に進める等のバグになる。「要素は固定、状態だけ書き換える」設計を初期から守る。
- アクション系のクリック・キー入力ハンドラ内では `_state.targets[target]` を **動的に** 参照する（`const t = ...; ()=> t.video` のクロージャキャプチャは避ける）。クリア時に状態オブジェクトを置き換える設計と相性が悪い。代替として状態は in-place リセットするか、毎回ルックアップする。
- `document.addEventListener('keydown', ...)` のようなグローバルリスナーをタブ表示のたびに増やしたくないので、モジュールレベルのフラグ（`_keysBound`）で一度だけ登録する。タブを離れても監視は続くが、`document.querySelector('.va-root')` で活性チェックすれば安全。

## 2026-08-29

- 言語切替の短縮表記を求められた場合は、言語名を推測で置き換えず、指定された文字列（今回は `JP` / `EN`）を実ブラウザ上の表示で確認する。翻訳状態だけで完了判定しない。
- モバイル用に絶対配置を通常フローへ戻すときは、背景の疑似要素が操作面を覆わないよう装飾層へ `pointer-events: none` を指定し、`elementFromPoint` または実クリックでヒット対象を確認する。
- デスクトップで成立する `minmax(260px, 1fr)` や2列グリッドは、親の内幅が小さいモバイルで文書全体を押し広げる。320px幅で `scrollWidth - clientWidth` を計測し、長い英語文言を含む実結果画面まで確認する。

## 2026-08-30

- UIを追加したときは閉じた初期状態だけでなく、トリガー操作後の展開状態を必ず画面検証する。モーダルは共通クラス名が付いていても外観定義を継承しているとは限らないため、背景、幅、余白、最大高、内部スクロール、モバイル幅をcomputed styleとスクリーンショットで確認する。
- 初期化済みDOMをデータ再読込のたびに`cloneNode`で置換すると、`addEventListener`で登録した操作が失われる。内容だけが変わる折りたたみUIは要素の同一性を保ち、冪等な初期化関数を再利用する。
- ブラウザで動的importするESモジュールは、既定の`node --check file.js`だけでは構文不正を見逃す場合がある。`node --input-type=module --check < file.js`またはテスト内の実importで検証し、実画面でも遅延読込される機能を開く。
- モーダルを開いた直後に下部入力へ自動フォーカスすると、スクロール領域が動いて役割・注意説明を飛ばしてしまう。冒頭を`scrollTop = 0`へ戻し、固定ヘッダーの閉じるボタンへフォーカスして、説明から順に読める状態を保つ。
- `responsive: true`だけではPlotlyの明示的な`layout.width`を打ち消せない。320pxで文書全体の`scrollWidth - clientWidth`を測り、グラフ、動的パラメータ入力、フローティングUIをすべて表示した最終結果画面で横超過0を確認する。
